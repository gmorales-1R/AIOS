## Architecture reminders

- Source of truth: `files/` — edit directly, no build step.
- Phaser bundle: local (`files/js/phaser.min.js`), vendored 2026-07-05 — no CDN dependency, matches `swarms`/`zhephone` convention.
- Asset paths: relative to `game.html`, served from `files/assets/` — generated by `code/prepare_assets.py`, which uses real Kenney source from `raw_assets/` when locally present (gitignored, not guaranteed) and falls back to placeholders otherwise. Always run it before relying on `files/assets/`.
- Serve with: `python3 -m http.server 8081 --directory games/bones/files`

## Isometric grid system

Confirmed from Kenney's own Tiled sample (`kenney_isometric-miniature-dungeon/Samples/Tiled Sample.zip`):

| Parameter | Value |
|-----------|-------|
| Tile canvas | 256 × 512 px |
| Grid cell | 256 × 128 px (tilewidth × tileheight in Tiled) |
| stepX | 128 px (half canvas width) |
| stepY | 64 px (half cell height) |
| Phaser anchor | `(0.5, 1.0)` — bottom-center of canvas |
| Depth sort | `col + row` ascending (painter's algorithm) |

Placement formula:
```
screen_x = originX + (col - row) * 128
screen_y = originY + (col + row) * 64
```

## Tile conventions (reference — applies if/when raw_assets/ is locally populated, see 2026-07-05 entry above)

- **Floor tiles**: use `_S` face from `kenney_isometric-miniature-dungeon/Isometric/`
  - `dirt_S.png` — plain dirt floor (border/outer)
  - `dirtTiles_S.png` — tiled dirt floor (interior)
  - `stone_S.png` — stone floor (accent)
  - `stoneInset_S.png` — inset stone (center/focal)
- **Bases pack** (`kenney_isometric-miniature-bases`): NOT for floors — use for pedestals, underground entrances, elevated platforms
- **Props**: use `_N` face for objects placed on tiles (barrel, chest, crate, etc.)

## Known gaps

- Placeholder art only in this checkout (procedurally generated) — real art activates automatically via `code/prepare_assets.py` if `raw_assets/` is populated locally; this sandbox specifically can't fetch kenney.nl to populate it itself.
- Witch is currently static (no movement) — summoning is the only implemented interaction.
- No walls, no obstacles, no pet AI/behavior beyond an idle bob tween.
- No persistence — pet count/positions reset on reload (no save wiring yet, unlike `swarms`).
- Scalability is only demonstrated at ~10 pets in manual testing — not yet stress-tested at the hundreds-scale the "unrestricted" identity implies.
